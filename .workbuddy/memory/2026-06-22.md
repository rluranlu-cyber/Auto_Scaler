# 2026-06-22 工作日志

## Blender 5.0.1 模型导入处理插件开发

**任务**: 开发适配 Blender 5.0.1 的插件，导入模型后自动创建空物体定位至底部中心，父级化所有模型至空物体，并把空物体的位移和缩放三轴乘以 0.0254（英寸→米换算）。

**用户确认的关键决策**:
- 触发方式：手动按钮（侧栏 N 面板 > Tool > Bottom Center Parent）
- 父子关系：Ctrl+P（parent_set, type='OBJECT', keep_transform=True）
- 缩放后行为：子模型跟随空物体联动（实现英寸→米的整体单位换算）
- 处理范围：仅新导入的物体（依赖 Blender 导入后自动选中的机制，用户执行前需保持选中状态）

**技术要点**:
- 用 obj.matrix_world @ v.co 收集所有选中 mesh 的世界坐标顶点，计算合并包围盒底部中心（X中心, Y中心, Z最小）
- 父级化时 keep_transform=True 保持子物体世界变换；之后修改父级 location × 0.0254 和 scale × 0.0254，子物体世界位置自动变为 0.0254 × 原位置，世界缩放变为 0.0254 × 原缩放，实现英寸→米的整体转换
- bl_info 中 blender 版本声明为 (5, 0, 1)，作为传统 legacy add-on 通过 Install from Disk 安装
- 暴露 conversion_factor、empty_name、empty_display_type、empty_display_size 四个可调参数

**交付文件**: `bottom_center_parent.py`（位于工作目录根）

**未验证项**: 无法在本地实际运行 Blender 5.0.1 测试，仅做了 Python 语法检查。用户需在 Blender 中实测确认。

## 插件迭代 v1.4（用户反馈：模型上面的空物体没有被删除）

**用户反馈**:
1. v1.3 中"模型上面的空物体没有被删除"——删除逻辑有 bug
2. Bip001 下的子级保护好了——保护逻辑正确
3. 明确需求：Bip001 子树不做清除，只挂载到新空物体下；其它所有网格体上有父级空物体的都解除并删除

**用户确认的 3 个关键决策**:
- "网格体"范围：仅 Mesh（不包括 Armature/Curve 等）
- 未选中父级 Empty：仅删选中的（不主动查找未选中的 Empty）
- Empty_A → Bip001 场景：保留 Empty_A（Bip001 上层 Empty 不删）

**v1.3 bug 根因**:
- 旧逻辑只删除"原本有子级、清除后无子级"的 Empty
- 但 Empty_A 不在选中集合时（导入器只选中顶层），它不在 empty_records 中，不会被删除
- 即使 Empty_A 在选中集合中，如果它仍指向其他子级（非空），也不会被删除
- 用户要求"全删"，不应有"原本有子级"的前置条件

**v1.4 新规则**:
1. 保护集：Bip001 子树（含自身）→ 不动、不 Alt+P、不删
2. Bip001 上层 Empty（_is_bip001_ancestor 判定）→ 保留
3. Alt+P 范围：仅 Mesh + 非 Bip001 子树 + 直接父级是 Empty
4. 删除范围：选中集合中所有 EMPTY 类型 + 非 Bip001 子树 + 非 Bip001 祖先 → 全删

**代码改动**:
- 删除 `_has_empty_ancestor()`（不再使用）
- 新增 `_is_bip001_ancestor(obj)`：从 Bip001 向上遍历祖先链，判断 obj 是否为 Bip001 祖先
- 重写 `_clear_empty_parentage()`：
  - to_clear 改为仅 Mesh + 直接父级是 Empty（不再用祖先链）
  - empties_to_delete 改为遍历 targets 中所有 EMPTY，排除 Bip001 子树和 Bip001 祖先
  - 删除前设置 safe_active 避免删除 active 物体时报错
- 版本 (1, 3, 0) → (1, 4, 0)
- 顶部注释、bl_info.description、Panel UI 同步更新

**副作用提示**（已写入 Panel UI）:
- Armature/Curve 等非 Mesh 几何体不做 Alt+P
- 删除其父 Empty 时 Blender 自动 parent→None，但世界变换可能跳变
- 用户明确"仅 Mesh"接受此副作用
